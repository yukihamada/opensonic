Solunaとは？

Solunaは、ネットワーク経由で低遅延オーディオを送受信するオープンソースシステムです。 業務用のDanteシステムと同じ役割を果たしますが、完全にオープンソース（MIT）で、 WiFi対応、ESP32対応（$5のマイコン）も計画されています。

できること

  • 複数デバイス間で48kHz/24bitオーディオ転送
  • PTPv2によるサブμs精度のクロック同期
  • 自由なチャンネルルーティングとミキシング
  • 1ms以下のレイテンシ（有線GbE）
  • CLIとREST APIで完全制御
  • Linux / macOS / Windows対応

Danteとの違い

  • ライセンス料不要（MIT）
  • WiFi + FEC + Opus圧縮対応
  • ESP32（$5）で動作可能
  • REST API/CLI/Web UIで設定
  • カスタムDSPプラグイン対応予定

ビルド方法

必要なもの

  • C++17対応コンパイラ（GCC 8+, Clang 10+, MSVC 2019+）
  • CMake 3.16以上
  • Linux: libasound2-dev（ALSA）
  • macOS: Xcode Command Line Tools（CoreAudio付属）
  • Windows: Visual Studio 2019+（WASAPI・Winsock2は標準搭載）

ビルド手順

# 1. リポジトリをクローン
git clone https://github.com/yourname/soluna.git
cd soluna

# 2. ビルドディレクトリ作成
mkdir build && cd build

# 3. CMake設定（テスト込み）
cmake .. -DSOLUNA_BUILD_TESTS=ON

# 4. コンパイル（並列ビルド）
cmake --build . -j$(nproc)

# 5. テスト実行（全213テスト）
ctest --output-on-failure

クロスコンパイル

# Raspberry Pi 4 (aarch64) 向けビルド
cmake .. -DCMAKE_TOOLCHAIN_FILE=cmake/toolchains/linux-aarch64.cmake

# Windows (MinGW-w64) 向けクロスビルド
cmake .. -DCMAKE_TOOLCHAIN_FILE=cmake/toolchains/windows-mingw.cmake
補足： Linux では sudo apt install libasound2-dev が必要です。 macOS は追加パッケージ不要で、CoreAudioが自動的にリンクされます。 Windowsでは avrt.lib（Multimedia Class Scheduler）が自動リンクされます。

デーモン（solunad）

solunadはオーディオの送信/受信を行うメインプロセスです。

送信モード（マイクやDAWの音をネットワークへ）

solunad --tx --device hw:0 --channels 2

受信モード（ネットワークの音をスピーカーへ）

solunad --rx --device hw:1 --channels 2
オプション説明デフォルト
--tx送信モード—
--rx受信モード—
--deviceオーディオデバイス名default
--channelsチャンネル数1
--dest送信先アドレス:ポート239.69.0.1:5004
--port受信ポート5004

CLIツール（solctl）

solctlはシステムの制御・監視を行うコマンドラインツールです。 すべての操作をターミナルから実行できます。

デバイス一覧

# 接続されたオーディオデバイスを表示
solctl devices

ルーティング操作

# ルート追加（デバイスA:チャンネル1 → デバイスB:チャンネル1）
solctl route add devA:1 devB:1

# ゲイン付きでルート追加（-6dB）
solctl route add devA:1 devB:1 -6

# ルート一覧
solctl route list

# ゲイン変更
solctl route gain devA:1 devB:1 -3

# ミュート ON/OFF
solctl route mute devA:1 devB:1 on

# ルート削除
solctl route remove devA:1 devB:1

ストリーム操作

# ストリーム作成（ソース → シンク、2チャンネル）
solctl stream create mic1 speaker1 2

# ストリーム一覧
solctl stream list

# ストリーム削除
solctl stream destroy 1

モニタリング

# チャンネルのレベルメーター表示
solctl meter devA:1

# システム状態
solctl status

# バージョン
solctl version

ルーティングの仕組み

Solunaのルーティングはチャンネル単位で行います。 各チャンネルは デバイス名:チャンネル番号 で指定します。

マイク (mic:1) ──┐ ├── ルーティングマトリクス ──┬── スピーカーL (spk:1) マイク (mic:2) ──┤ (ゲイン/ミュート) ├── スピーカーR (spk:2) │ │ DAW (daw:1) ─────┤ ├── ヘッドフォンL (hp:1) DAW (daw:2) ─────┘ └── ヘッドフォンR (hp:2)

できること：

  • 1対1: mic:1 → spk:1（シンプルな接続）
  • 1対多: mic:1 → spk:1, mic:1 → hp:1（スプリット）
  • 多対1: mic:1 + daw:1 → spk:1（ミキシング）
  • ゲイン制御: 各ルートに個別のdBゲイン設定
  • ミュート: 音を切らずにルートを一時停止
  • メーター: Peak/RMS/クリップカウントをリアルタイム監視

WiFi対応（Phase 4）

SolunaはWiFi経由でも安定したオーディオ配信を実現します。 ネットワーク品質を自動監視し、FEC（前方誤り訂正）やジッタバッファを動的に調整します。

WiFi品質レベルと自動適応

品質ジッタパケロスFECバッファOpusビットレート
Excellent<1ms<0.1%なし2ms128kbps
Good<3ms<1%XOR4ms96kbps
Fair<5ms<3%XOR6ms80kbps
Poor<10ms<5%RS10ms56kbps
Critical>10ms>5%RS(max)15ms32kbps

FEC（前方誤り訂正）

XOR パリティ（軽量）

  • 5パケットごとに1パリティ
  • 1パケットロスを復元可能
  • CPU負荷が極めて低い
  • ESP32向け

Reed-Solomon（高耐性）

  • 5パケットに2-4パリティ
  • 複数パケットロスから復元
  • デスクトップ向け
  • 品質悪化時に自動切替

Opus圧縮（オプション）

WiFi帯域が制限される場合、Opusコーデックで圧縮できます。 ネットワーク品質に応じてビットレートを32-128kbpsの範囲で自動調整します。 Packet Loss Concealment (PLC) により、ロスしたパケットの音声を補間します。

よくある使い方

例1: 2台のPC間でステレオ音声を送る

# 送信側PC（マイク入力 → ネットワーク）
solunad --tx --device hw:0 --channels 2

# 受信側PC（ネットワーク → スピーカー出力）
solunad --rx --device hw:1 --channels 2

例2: ルーティングで複数マイクをミックス

# マイク1とマイク2をスピーカーLにミックス
solctl route add mic:1 speaker:1 0
solctl route add mic:2 speaker:1 -6   # マイク2は-6dBで

# ルート確認
solctl route list

例3: ライブ中にミュート/解除

# MC用マイクをミュート
solctl route mute mc_mic:1 pa:1 on

# MC登場、ミュート解除
solctl route mute mc_mic:1 pa:1 off

AES67互換モード（Phase 7）

SolunaはAES67デバイスとの相互運用を可能にするAES67互換モードを搭載しています。 solunad --aes67 で有効化すると、標準RTPパケット（OSTP拡張ヘッダなし）を送信し、 SAP/SDPでセッションをマルチキャストアナウンスします。

注意： AES67「互換」であり、完全なAES67認証ではありません。 標準的なAES67デバイスとの基本的な相互運用を目的としています。

AES67モードの特徴

  • 標準RTPパケット（OSTP拡張ヘッダなし）
  • ペイロードタイプ: L24 (PT=10)、L16 (PT=11)
  • SAP マルチキャスト（224.2.127.254:9875、30秒間隔）
  • SDP v=0/o=/s=/c=/t=/m=audio 形式のセッション記述
  • PTP IEEE1588-2008 タイムスタンプリファレンス
# AES67互換モードで送信
solunad --tx --aes67 --device hw:0 --channels 2

# CMakeビルド時にAES67を有効化
cmake .. -DSOLUNA_ENABLE_AES67=ON

Web制御UI（Phase 7）

solunadに内蔵されたWebアプリケーションから、ブラウザでシステムを制御できます。 外部ライブラリ不要 — HTML/JS/CSSはビルド時にバイナリに埋め込まれます。

アクセス方法

# solunadを起動（ポート8400でWebサーバが自動起動）
solunad --tx --device hw:0

# ブラウザで開く
http://localhost:8400/

Web UIの機能

  • デバイス一覧: ネットワーク上のSolunaデバイスを表示
  • ストリーム管理: ストリームの作成・削除
  • ルーティングマトリクス: ルート追加・削除・ゲイン・ミュート
  • レベルメーター: リアルタイムオーディオレベル表示
エンドポイント説明
http://host:8400/Web UI（index.html）
ws://host:8400/wsWebSocket（JSON制御プロトコル）

DTLS暗号化（Phase 7、オプション）

UDPトランスポートにDTLS 1.2暗号化を追加できます。 OpenSSLが必要です。solunad --dtls で有効化します。 

# DTLSを有効にしてビルド
cmake .. -DSOLUNA_ENABLE_DTLS=ON

# DTLS暗号化モードで送信
solunad --tx --dtls --device hw:0

DTLS仕様

  • DTLS 1.2（RFC 6347）
  • UdpSocketと同じインターフェース（透過的に暗号化/復号）
  • 自己署名証明書で動作（テスト用）
  • OpenSSLが見つからない場合は自動的にスキップ

DSPプラグイン（Phase 7）

共有ライブラリとしてビルドされたDSPプラグインを実行時にロードできます。 C ABIによるプラグインインターフェースで、ゲイン・EQ・コンプレッサーなどの処理を オーディオパイプラインに挿入できます。

プラグインの使い方

# ゲインプラグインをロードして送信
solunad --tx --plugin path/to/gain_plugin.so --device hw:0

# サンプルプラグインのビルド
cd build
cmake --build . --target gain_plugin

プラグインAPI

// C ABIエントリポイント
extern "C" {
    DspPlugin* soluna_plugin_create();
    void soluna_plugin_destroy(DspPlugin*);
}

// DspPluginインターフェース
class DspPlugin {
    virtual const char* name() const = 0;
    virtual bool init(uint32_t sample_rate, uint32_t channels) = 0;
    virtual void process(float* buffer, size_t frames, uint32_t channels) = 0;
};

ESP32ファームウェア（Phase 6）

ESP32-S3 ($5) で動作するスタンドアロンファームウェアです。 WiFi接続、PTP同期、RTP送受信、XOR FEC、mDNS発見、バイナリ制御をすべて内蔵しています。

ビルド方法

# ESP-IDF環境を有効化
. $IDF_PATH/export.sh

# ESP32ファームウェアをビルド&書き込み
cd apps/esp32
idf.py build
idf.py -p /dev/ttyUSB0 flash monitor

ESP32モジュール構成

モジュール機能特記
sol_i2sI2S + DMA オーディオI/OCore 1固定、STDモード

ESP32設計制約

  • malloc禁止: オーディオパスでの動的メモリ確保なし（全バッファ静的確保）
  • デュアルコア: WiFi/Net = Core 0、Audio/I2S = Core 1
  • SRAM <200KB: リングバッファ・FECバッファを含めてSRAM使用量を最適化
  • C互換: C++例外・RTTIなし、ESP-IDF v5 APIのみ使用
  • NVS設定: WiFi SSID/パスワード、チャンネル数、モードをNVSに永続化

ESP32 OTAアップデート（Phase 7）

ESP32ファームウェアをネットワーク経由で無線アップデートできます。 バイナリ制御プロトコルでファームウェアチャンクを送信し、 ESP-IDF OTA APIで書き込みます。

OTAの使い方

# Pythonツールでファームウェアをアップロード
python3 tools/esp32_ota.py 192.168.1.200 build/soluna_esp32.bin

OTAプロトコル

コマンドID方向説明
OTA_BEGIN0xF1Host → ESP32ファームウェアサイズ送信
OTA_READY0xF4ESP32 → Host準備完了
OTA_WRITE0xF2Host → ESP321024Bチャンク + シーケンス番号
OTA_ACK0xF5ESP32 → Hostチャンク受信確認
OTA_FINISH0xF3Host → ESP32検証 + 再起動
ロールバック: 新ファームウェアのブートが失敗した場合、 ブートローダーが自動的に前のパーティションへ復帰します。 成功した場合は sol_ota_confirm_boot() で確定します。
